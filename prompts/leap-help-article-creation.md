# Leap ヘルプページ記事 作成プロンプト（自己完結版）

このファイル1つだけで、過去のログ・チャット履歴・メモリを一切参照せずに、Leapサイトの「ヘルプページ」（`/help/`配下）に記事を追加できるようにするためのプロンプトです。新しい記事を作りたいときは、このファイルの内容をそのままAIエージェントに渡して依頼してください。

---

## 1. このコンテンツの性質（最重要・誤解しやすい点）

ヘルプページは、`ja/ec-guide/`配下の「ECガイド記事」（SEOブログ記事、Leapのブランド訴求・FAQ・まとめを含む）とは**まったく別物**です。

- ヘルプページの記事は、**BASEのヘルプセンター（https://help.thebase.in/hc/ja）のカテゴリ構成・粒度を参考にしつつ、内容は「BASEの操作方法」ではなく「Leap自身（app.leap.site）の操作方法」として書く**
- つまり「BASEのヘルプ記事を翻訳する」のではなく、「BASEのヘルプ記事と同じような粒度・トピックで、Leapの実際の画面操作を説明する記事を新規に書く」というタスク
- 文体はブログ記事ではなく、BASEのヘルプ記事のような**シンプルな操作説明**にする

### 含めないもの（ECガイド記事との違い）
- 「【1分で解説！】」のようなオーバービュー見出し
- FAQコーナー
- 「まとめと気づき」
- Leapのブランド訴求・AI E-Commerce Agentの思想・CTAリンク（ブログ・お問い合わせへの誘導）
- 参考資料・出典一覧
- サムネイル画像（後述、意図的に使わない方針）

### 含めるもの
- 1〜2文の簡潔な導入
- 番号付きの手順（`1. 2. 3.`）
- 必要に応じて「〇〇できないときは」「注意点」のような短い補足セクション
- 関連する他のヘルプ記事への内部リンク（自然に必要な場合のみ）

---

## 2. 最重要ルール：不確かな情報は絶対に補完しない

**私（AIエージェント）は、Leapの実際の製品画面（app.leap.site）にアクセスできません。** ログイン認証が必要なアプリであり、このリポジトリのソースコードにも含まれていません。

したがって、記事の中で実際の画面・入力項目・ボタン名・エラーメッセージなどに言及する場合、**必ず事前にユーザーからスクリーンショットまたは詳細な説明をもらってから書く**こと。

- わからないことがあれば、想像で埋めずに必ず質問する
- 「だいたいこうだろう」という推測で手順や画面項目を書かない
- 一般的な内容（例：商品登録のルール、決済方法の考え方など、Leapの具体的な画面操作を伴わない説明）であれば、この確認は不要
- スクリーンショットをもらったら、そこに写っている項目名・ボタン名・文言をできるだけそのまま使う（意訳・想像で言い換えない）

---

## 3. 進め方

1. 次に書くトピックを1つ決める（下記「7. トピック候補」を参照、または依頼者に確認）
2. そのトピックを書くために必要な画面情報が今の会話内にあるか確認する
3. 不足していれば、必要なスクリーンショット・情報を具体的に列挙して依頼者に質問する（複数まとめて聞いてよい）
4. 情報が揃ったら、1本だけ記事を作成する（まとめて何本も作らない。1本ずつ確認しながら進める）
5. ビルド確認（`npx @11ty/eleventy`）を行い、生成されたページのURLを伝える
6. 依頼者の確認を得てから次のトピックに進む

日本語版から1本ずつ進める。英語版・中国語簡体字版は、依頼者から明示的に指示があるまで作らない。

## 4. ファイル配置とfront matter

### 4.1 保存先
`<locale>/help/<category>/<slug>.md`

`locale`は`ja`（まずはここから）。`category`は下記6種類のいずれか。`slug`は英数字ハイフン区切りの短い識別子（例：`create-account`, `login`）。

### 4.2 6カテゴリ（`_data/help_topic_translation.json`で定義済み）

| category slug | 内容 |
|---|---|
| `account-setup` | ショップ開設・アカウント管理 |
| `products` | 商品登録・在庫管理 |
| `payments` | 決済・振込 |
| `orders` | 注文・発送・キャンセル対応 |
| `design-marketing` | デザイン・集客・販促 |
| `security` | セキュリティ・トラブル対応 |

新しいカテゴリを追加する必要が出た場合は、依頼者に確認してから`_data/help_topic_translation.json`にも追加すること（ファイル単体を作成するだけでは表示されない）。

### 4.3 Front Matter テンプレート

```yaml
---
layout: help-post.njk
title: 記事タイトル（シンプルな操作説明タイトル。例：「Leapにログインする方法」）
description: 100〜150字程度のmeta description
date: 2026-08-12T09:00:00
topic: <category-slug>
locale: ja
tags:
  - help
  - タグ2
author: Leap 編集部
author_image: https://placehold.co/100x100/e2e8f0/94a3b8?text=Leap
author_bio: ECサイト運営のサポートチーム
---
```

**重要：`thumbnail`フィールドは含めない。** ヘルプページはサムネイル画像を使わない方針（依頼者の指示）。`help-post.njk`および一覧・カテゴリページ側は、`thumbnail`が無指定の場合に画像枠自体を非表示にする実装済みのため、何も追加作業は不要。誤って`thumbnail`を追加しないこと。

**`date`には時刻まで含める。** 同じ日に複数記事を作る場合、後から作った記事ほど時刻を遅くする（例：1本目 `09:00:00`、2本目 `10:00:00`）。ヘルプページの一覧・カテゴリページは「登録順（古い記事が先、新しい記事は末尾）」がデフォルト表示順になっているため、日時の前後関係が表示順に直結する。同じdatetimeを使うと表示順が不安定になるため避けること。

### 4.4 本文の構成（シンプルな手順説明）

```markdown
（1〜2文の導入）

## （手順の見出し。例：新規登録の手順）

1. ...
2. ...
3. ...

## （補足・注意点があれば）

- ...

## （関連記事があれば、自然な形でリンク）

[別の記事タイトル](/ja/help/<category>/<slug>/) を参照してください。
```

見出しは`##`（front matterの`title`が自動的にH1になるため）。FAQ・まとめ・CTA・参考資料は入れない。

## 5. サムネイル・画像に関する実装状況（背景情報）

- `_includes/help-post.njk`、および`ja/help/list.njk`と6カテゴリの`index.njk`（en/zh-hansも同様に計21ファイル）は、`{% if thumbnail %}` / `{% if post.data.thumbnail %}`で画像ブロック全体を囲ってあり、`thumbnail`未指定時は画像枠自体が表示されない
- これはECガイド（`ec-guide-post.njk`等）とは異なる実装。ECガイド側は元のプレースホルダー画像（`https://placehold.co/...`）表示のままにしてあるので、**ECガイド側のファイルは絶対に変更しないこと**

---

## 6. 表示順に関する実装状況（背景情報）

- ヘルプページの一覧・カテゴリページ（`list.njk`と6カテゴリの`index.njk`、ja/en/zh-hans計21ファイル）は、デフォルトの並び替えを「登録順（昇順、日付が古い記事が先頭）」に変更済み
- ボタンラベルも変更済み：`新着順`→`登録順`、`人気順`→`新しい順`（en: `Newest`→`Order added`、`Popular`→`Newest first`。zh-hans: `最新`→`默认顺序`、`热门`→`最新优先`）
- `ja/help/index.njk`（トップページ）の「新着記事」セクションは新着順のまま（意図的な仕様、変更不要）
- 新しい記事を追加した際、この並び順は自動的に効くため、テンプレート側の追加作業は不要。**ただし4.3で述べた通り、`date`に時刻を含めて前の記事より後の時刻にすることを忘れないこと**

## 8. ビルド確認・技術的注意点

- 記事作成後は必ず`npx @11ty/eleventy`を実行し、エラーなく完了することを確認する
- `docs/ja/help/<category>/<slug>/index.html`が生成されているか確認する
- `docs/`はビルド出力先で`.gitignore`対象。コミット対象に含めない
- リポジトリ直下はEleventyの入力ディレクトリなので、`prompts/`ディレクトリ（本ファイルの置き場所）は`.eleventyignore`で除外済み。新しい種類の内部ドキュメントを追加する場合も、ビルド対象に含めないよう注意する

## 9. Gitワークフロー

記事作成後のコミット・プッシュ・PR作成は、必ずユーザーに実行内容を伝え、承認を得てから行う（無断で実行しない）。手順は以下の通り。

1. `git checkout main` → `git pull origin main`
2. 既存の作業ブランチを使う（なければ`git checkout -b <ブランチ名>`）
3. `git add` → `git commit` → `git push origin <ブランチ名>`
4. GitHub上でPull Requestを作成
